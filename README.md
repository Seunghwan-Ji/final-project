# 기초 다지기
## 기초 학습
머신러닝과 딥러닝의 차이점을 이해하고, 지도학습, 비지도학습, 강화학습의 개념을 학습. 지도학습의 분류 및 회귀 문제에 적합한 알고리즘과 활성화 함수를 배움.

## 딥러닝 실습
TensorFlow를 사용하여 신경망을 설계하고, 표 형태의 데이터와 이미지 데이터로 실습. CNN을 통해 이미지 데이터에서 패턴을 학습하는 과정을 이해함.

## YOLO 모델
CNN 구조의 객체 탐지 모델인 YOLO를 학습하고, 'Roboflow' 사이트의 메타 데이터를 사용해 모델을 파인튜닝. 파인튜닝 후 예측을 수행해 결과를 확인함.

## GPU 연산
NVIDIA GPU를 사용하여 딥러닝 모델의 학습 속도를 향상시키기 위해 CUDA와 cuDNN을 설치. PyTorch를 통해 GPU 연산을 수행하고, GPU의 병렬 처리 능력의 중요성을 인식함.

# 프로젝트 시작
## 데이터 수집
'Roboflow'에서 두 개의 데이터셋을 수집. 하나는 라벨링이 완료되었고, 다른 하나는 라벨링이 되지 않았음.

## 데이터 전처리
라벨링이 없는 데이터의 train 이미지만 활용하여 train : test = 7 : 3 비율로 분할.
train 데이터를 다시 train : valid = 7 : 3으로 분리.
각각의 데이터셋에 대해 labels 폴더를 생성하고, 직접 라벨링한 텍스트 파일을 추가함.

## 데이터 통합 및 클래스 통일
두 데이터셋의 클래스를 통합하고 중복되는 클래스를 하나의 번호로 통일.
중복되지 않는 클래스는 기존 클래스 번호 뒤에 이어서 번호 매김.
통합된 데이터를 기준으로 새로운 yaml 파일 생성.

## 모델 파인튜닝 및 평가
통합된 데이터셋으로 모델을 파인튜닝한 후, 테스트 이미지에서 예측을 수행하여 결과를 확인함.

# 기술, 알고리즘
## NMS (Non-Maximum Suppression) 알고리즘:
- 기본 개념:
  - 동일 객체에 대해 여러 바운딩 박스가 탐지될 때, 신뢰도 기준으로 가장 높은 박스를 선택하고 중복 박스를 제거함.
  - 박스들을 신뢰도에 따라 내림차순 정렬 후, 가장 신뢰도가 높은 박스를 선택하고 겹치는 다른 박스들을 IoU 기준으로 삭제함.
  - 이 과정을 반복하여 최종 바운딩 박스를 결정함.
- 문제점:
  - 과적합된 모델이 높은 신뢰도로 잘못된 예측을 할 수 있어, NMS에서 이 박스가 선택되는 문제 발생.
  - 일부 모델이 잘못된 예측을 하고 높은 신뢰도를 보일 때, 올바른 예측을 하는 모델의 결과가 덮어질 수 있음.
- 다수결 알고리즘:
  - 앙상블 기법 중 하나로, 여러 모델의 예측 결과를 기반으로 다수결 방식으로 최종 예측을 결정하여, 과적합 문제를 완화하려고 함.

## 다수결 알고리즘
- 기본 개념:
  - 여러 모델의 탐지 결과에서 가장 많이 나온 라벨을 결정하는 방식.
- 겹침 계산:
  - 박스들 간의 IoU(Intersection over Union)를 계산하여 겹침 정도를 판단.
  - IoU가 특정 임계값보다 크거나 작으면 박스가 많이 겹쳤다고 판단할 수 있음.
- 그룹화 이유:
  - 하나의 객체를 포착한 여러 박스가 있을 때, 이들 박스를 그룹화하여 적합한 박스 좌표, 신뢰도, 라벨을 결정하기 위해서.
  - 특정 임계값을 기준으로 겹침 정도를 판단하여 그룹화를 수행, 다른 객체의 박스가 같은 그룹에 포함되지 않도록 함.
- 결정 방법:
  - 박스 좌표: 그룹 내 박스들의 좌표 평균.
  - 신뢰도: 그룹 내 박스들의 신뢰도 평균.
  - 라벨: 그룹 내 라벨 중 빈도수가 가장 높은 것.
- 결과 표시:
  - 프레임 이미지에 결정된 박스 좌표에 사각형을 그리고, 라벨과 신뢰도를 텍스트로 표시함.
- 문제점 및 개선:
  - 여전히 일부 과적합 모델로 인해 결과에 문제가 발생함.
  - 과적합 모델을 제외하고 추가 조건을 적용하여 개선하며, 특정 조건에서는 NMS 방식을 사용하기로 함.

## 알고리즘 통합 및 최종 기술
1. 모델 감지 결과 수집:
   - 예시: '[1, 2, 2, 0, 1, 1, 0, 1]'
   - 총 8개의 객체가 감지되었으며, 각 모델이 감지한 객체의 수를 나타냄.
2. 겹치는 박스 그룹화:
   - 예시: '[[0], [1], [2, 4, 7], [3, 6], [5]]'
   - 서로 겹치는 박스들을 그룹화. 특정 임계값 이상의 겹침을 기준으로 그룹 형성.
3. 그룹 필터링:
   - 예시: '[[2, 4, 7]]'
   - 적어도 3개 이상의 박스가 겹치는 그룹만 남김.
4. 라벨 결정:
   - 예시: '['계란', '계란', '감자']'
   - 그룹 내 박스들의 라벨 빈도수를 조사하여 최빈값 결정. 최빈값이 여러 개일 경우 NMS 방식을 적용하여 신뢰도가 높은 박스의 라벨 선택.
   - 빈도수가 모두 1인 경우에는 모든 박스에 NMS를 적용하여 신뢰도가 높은 박스의 정보를 선택.
5. 성능 개선:
   - 모델 예측 수행 속도 개선을 위해 각 모델에 대해 스레드를 생성하고 병렬로 예측 수행.
   - 모든 스레드가 종료될 때까지 기다리고, 예측 결과를 기반으로 앙상블 기법을 적용하여 최종 예측을 결정함.

# 탐지된 식재료를 활용한 레시피 추천 기능
## 탐지된 식재료 집합 생성
웹캠에서 매 프레임마다 최종 예측된 식재료 정보를 집합에 저장.
집합을 사용하여 중복된 라벨을 방지하고 이를 '탐지된 식재료 집합'으로 명명.

## 레시피 데이터 준비
'KADX'와 '만개의 레시피' 사이트에서 한식 레시피 데이터를 CSV 파일로 다운로드.
'Pandas' 라이브러리로 데이터 프레임으로 변환하여 약 18.5만개의 행을 확인.
주요 열: '요리명', '재료리스트', '조회수', '추천수', '스크랩수', '요리타입', '음식분위기', '재료타입', '음식타입', '몇인분', '요리난이도', '요리시간', '레시피일련번호'.

## 레시피 필터링 및 정렬
옵션 1: '탐지된 식재료 집합'에 포함된 재료가 많을수록 우선 순위를 매김.
   - 데이터 프레임에 '포함된 재료 개수'와 '포함된 재료' 열을 추가.
   - '포함된 재료 개수' 기준으로 내림차순 정렬하여 상위 레시피를 표시.

옵션 2: 모든 재료가 '재료리스트'에 포함된 레시피만 추출.

사용자 선택에 따라 '추천순', '조회순', '스크랩순' 중 하나로 추가 정렬 가능.
   - 각 정렬 기준에 따라 '추천수', '조회수', '스크랩수' 열을 내림차순 정렬.
   - 데이터 타입을 정수로 변환하는 전처리 작업 포함.

## 상세 안내 제공 고려

# 레시피 선택 시 상세 안내 시각화 기능
## 레시피 데이터 스크래핑
'만개의 레시피' 사이트에서 요리명 검색 결과를 기반으로 상세 정보를 제공하기 위해 스크래핑 기술 사용.
사용자가 선택한 요리명과 사이트 주소를 결합해 URL을 생성.
'requests' 라이브러리로 해당 URL에 HTTP GET 요청을 보내고, 응답받은 HTML을 'BeautifulSoup'으로 파싱.

## 검색 결과 처리
사이트의 검색 결과는 한 페이지에 40개씩 표시되며, 동영상 포함 여부에 따라 레시피를 선택.
1페이지 내에서 동영상이 포함된 결과를 우선적으로 선택하고, 찾지 못하면 추천순으로 나열된 첫 번째 결과를 선택.
선택된 결과를 기반으로 새로운 URL을 생성하고, 다시 GET 요청을 보낸 후 HTML 데이터를 파싱.

## 세부 정보 추출
파싱된 HTML에서 다음 정보들을 추출:
'요리된 사진', '재료 구성', '요리 영상', '조리 순서/이미지', '팁/주의사항'.
조리 순서 부분에서는 메인 설명과 부연 설명을 split하여 줄바꿈 문자로 연결해 가독성을 높임.

## 결과 시각화
추출된 정보를 기반으로 사용자가 선택한 레시피의 상세 안내를 시각적으로 제공.

# 비슷한 레시피 추천 기능
## 특징 열 선정 및 전처리
사용자의 '관심 요리 목록'에서 선택된 하나의 레시피와 유사한 레시피를 추천하기 위해 주요 열(특징 열)을 선정.
결측값이나 오류가 있는 데이터는 제거.
'재료리스트' 열은 CountVectorizer를 사용해 텍스트를 벡터화.
'요리타입', '음식분위기', '재료타입', '음식타입', '몇인분', '요리난이도', '요리시간' 열은 OneHotEncoder로 범주형 변환.

## 유사도 계산
선택된 레시피와 다른 레시피 간의 유사도를 코사인 유사도 알고리즘을 통해 계산.
유사도가 높은 상위 10개의 레시피를 추천 목록으로 추출.

# 웹사이트 적용
## 웹사이트 구성
Streamlit 라이브러리를 사용해 웹 애플리케이션을 개발.
페이지는 사이드바 메뉴(왼쪽)와 선택한 메뉴에 따른 페이지(오른쪽)로 구성.

## 사이드바 메뉴
### 메인 메뉴
기본적인 설명과 이미지를 표시.

### 카메라 식재료 인식
실시간 식재료 탐지 기능을 실행하고, 탐지된 식재료를 수정 및 레시피 추천 기능으로 이어짐.

### 식재료 직접 입력
사용자가 직접 식재료를 입력하고 레시피를 추천받음.

### 무작위 요리 추천
랜덤 레시피를 보여줌.

### 관심 요리 목록
사용자가 저장한 레시피를 관리하고, 비슷한 레시피를 추천받음.

### 요리 검색 기록
사용자가 조회한 레시피를 기록.

## 기능 구현
### 레시피 추천
탐지된 식재료를 기반으로 조건에 맞는 레시피 추천.

### 레시피 상세 안내
선택한 레시피에 대한 상세 정보를 스크래핑해 시각적으로 제공.

### 비슷한 레시피 추천
선택한 레시피와 유사한 레시피를 추천.

## UI 및 세션 관리
각 버튼과 텍스트에 스타일링을 적용해 가독성 향상.
세션 상태 관리를 통해 페이지 전환과 UI 재구성.
각 메뉴마다 관련 페이지를 모듈화하여 일관성과 유지보수를 용이하게 함.

# 개선할 점 및 강화된 역량
## 보완할 점
### 모델 개선
다수결 방식에서 불리하게 작용할 수 있는 일부 모델의 클래스 부족 문제를 해결하기 위해 클래스가 중복되는 모델들을 모아 문제를 해결.
더 많은 데이터셋으로 파인튜닝된 모델을 사용해 성능을 개선할 수 있음.

## 추가할 기능
### 날씨와 계절 기반 추천 
계절별 인기 메뉴 데이터와 날씨별 배달 음식 주문 데이터를 수집.
Open API를 사용해 현재 날씨를 분석하고, 'datetime' 라이브러리로 계절을 그룹화 한다음 수집한 데이터와 현재 날씨, 계절을 매칭해 맞춤형 레시피 추천.

## 강화된 역량
### 컴퓨터 비전 딥러닝 기술 활용 능력
YOLO 모델을 활용한 실시간 객체 탐지 및 모델 파인튜닝 과정에서 딥러닝 기술 실제 활용 및 응용 능력 향상.

### 문제 해결 능력
앙상블 기법의 알고리즘들을 결합해 모델의 과적합 문제 해결 및 모델 성능을 개선.
멀티 스레딩 방식으로 다수 모델이 병렬로 예측을 수행하게 하여 속도 최적화 문제 해결.

### 데이터 전처리 및 분석 능력
다양한 데이터셋을 수집, 라벨링, 통합하는 과정을 통해 데이터 전처리 능력 향상.
레시피 데이터셋의 데이터를 다양한 정렬 기준으로 추출하는 과정에서 데이터 분석 능력 향상.

### 웹 개발 및 데이터 과학 기술 연동
Streamlit을 사용해 웹 애플리케이션을 구축하면서 여러 페이지를 로드하고 관리하는 기술과 AI 모델 및 데이터 프레임을 연동하는 기술 향상.

### 협업 및 프로젝트 관리 능력
나를 포함한 팀원들의 부족한 지식을 팀장으로서 공부 방향성을 지시하고, 학습한 내용을 소통을 통해 강의함.
프로젝트 전반에서 각 팀원의 강점에 맞춘 역할 분담을 통해 효율적인 협업을 이끔.
팀장으로서 팀원의 업무 상황을 파악하고, 필요한 부분에서 지원하거나 조언을 제공하여 팀 전체의 생산성을 극대화.
기초 학습부터 웹사이트 구현까지의 여러 단계로 이루어진 프로젝트를 체계적으로 관리하고, 각 단계별 마감일을 설정하여 일정에 맞춰 진행.
